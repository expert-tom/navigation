# 问题清单复核与新版处理

审查输入：用户 `问题.txt`、现有源代码、提供的 `rules.md` 与导航协议。规则及协议为唯一赛道依据，其他agent报告中的推断不当作实测事实。

## 结论

旧版最大的缺口不是把某个控制量加大，而是缺少完整的“保存地图→重启后在同一地图定位→有质量依据的位姿→按地图坐标执行任务”链路。新版补齐这条链路，但没有现场输入，不能宣称USB根因已解决或完整实车已跑通。

| 清单项目 | 核实与处理 |
| --- | --- |
| TF帧对不上 | 有实质风险，但未采集实车消息前不能断定实际帧一定为camera_init/body。新增可配置桥接，明确组合T_odom_body与T_body_base；AMCL提供map→odom，不伪造全局TF。隔离race帧防止与原树重名。 |
| 等不到/map | 单独FAST-LIO不等于地图服务器；但过去截图中曾存在/map，不能说整车从未发布过。新版明确启动地图服务器并验证收到的地图与所选文件一致，不依赖未知后台地图。 |
| 定位心跳无发布者 | 新增真正的AMCL协方差、扫描/地图一致性、里程计时效及稳定等待监测，不再等不存在的Bool，也不把全零协方差解释成高精度定位。 |
| 停车帧第一次失败就break | 已改为20次有间隔、有限重试，记录尝试/成功次数，保留首个故障；不自动恢复运动。写入成功也不是执行ACK，断链仍无法保证物理停车。 |
| 0.05m/s调试限速与评分 | 不再在比赛设置中强制覆盖为0.05；速度来自field文件，默认仍是低速调试档。协议量不是m/s，须拟合实车矩阵。取消不可配置的0.2总上限，改为默认0.2、确认标定后才允许提高到显式已验收范围，当前实现最多1。不能凭路线理想用时推断具体得分。 |
| 大点云逐点Python阻塞 | PointCloud2点数/步长先验收，再NumPy向量化；单在途+单最新待处理任务，不排无限队列，重计算和有限TF等待在worker。原始时间保留，超时结果不能刷新心跳；规划有预算，发送侧另设独立数据截止时间。 |
| max_obstacles=2500 | 新点云通路按体素和物理场地范围界定预算，保留全部占据格，不以2500个格硬停，也不静默丢障碍。地图仍有显式内存上限，超限要改变合理分辨率/范围并重验，不能忽略。 |
| min_height=0.08 | 默认改为相对地面base的0.03m，但必须校准外参和验证地面误检、底座可见性。底座半径同时写入固定障碍；不能凭照片断言旧过滤会完全抹掉所有底座。 |
| parking写死 | 新入口要求在保存地图上选点，field绑定地图digest；旧示例坐标不能直接用于新地图。离线预检地图覆盖、未知区域、路线与底座碰撞。 |
| 位姿跳变永久锁 | 保留真正跳变锁定，避免车辆在错误定位下自动重启；普通临时障碍/短暂定位失效可暂停恢复。人挡雷达不等于一定发生真实位姿跳变；不能为考核避障而取消跳变保护。新一轮安全停车后重启任务。 |
| 消息时间基准 | 不把接收时间当消息新鲜度；输入必须有可解释的ROS时间。新鲜度转换到单调时钟，错误纪元、回拨和未来时间拒绝。未确认时间之前不允许桥接。 |
| TF timeout=0 | 控制侧只做非阻塞最新查询，短暂查询失败保留尚未过期的最后样本；点云worker有限等待TF。既不每丢一帧就销毁有效缓存，也不无限续期旧数据。 |
| 没有自动发车 | 规则只说裁判开始后自主执行，没有指定电子信号。提供一次明确start服务，之后不接受人工运动修正；不得擅自解释game_progress或开机就跑。起跑触发须赛前与裁判确认。 |

## 对之前串口诊断的更正

- 正常timeout返回空字节不是同一异常，不能统一忽略。
- select可读后读取0字节可能涉及挂断、驱动、控制线、并发等，不是已证实“只可能两种原因”。无权限的fuser/proc检查不能证明无人占用。
- 原先贴出的接收线程捕获异常后退出，不是已经证实存在空转烧CPU。新版异常观察路径仍主动节流。
- 0.02失败、0.01成功不足以说明协议拒绝0.02；只接收也失败说明不能只归因于速度。读取错误来源于系统/串口状态，但代码的控制线初始化、并发及故障策略可能影响表现，须分层验证。
- 宽限期继续发送非零指令不适合这个无下位机超时保护的设备。新版第一次异常即锁住非零，宽限只用来零速观察。不能保证这样就修好了物理USB问题。

## 新版仍未替代的实车工作

公开雷达/LIO在个人环境的部署；网络及ROS发现；真实帧与外参；操控模式和独立急停；双轴速度/死区/制动标定；地图质量与AMCL收敛；底座及整车外廓；比赛完整路线和人为干扰验收。PCD参考导出不是三维回环地图优化，也不是3D ICP定位。

桌面报告覆盖程序行为，不覆盖硬件正确性。当前不应称为“比赛已完成”，应称为“预建图方案软件候选实现完成，待ROS与实车集成验收”。

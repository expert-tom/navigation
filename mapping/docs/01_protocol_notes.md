# 导航赛道：第一个离线任务

本项目实现上位机到下位机的19字节控制帧，并对照官方协议测试。
使用Python 3标准库，不需要额外安装依赖。不会打开串口或控制车辆。

## 运行

在此文件夹打开终端，执行：

```powershell
python navigation_protocol.py
python -m unittest -v
```

如果你的电脑使用Python启动器，可以把`python`换成`py -3`。

第一条命令默认生成停车帧，预期输出：

```text
A5 0C 00 01 26 00 00 00 00 00 00 00 00 00 00 00 00 18 9F
```

也可以生成其他离线指令：

```powershell
python navigation_protocol.py --vx 1 --vy -1 --wz 3 --seq 1
python navigation_protocol.py --vx 0.1 --vy 0 --seq 2
```

第一组数值来自协议测试向量，只用于核对编码，不是实车推荐速度。

## 如何读懂停车帧

| 字节偏移 | 内容 | 含义 |
|---|---|---|
| 0 | A5 | 帧起始标记 |
| 1–2 | 0C 00 | 小端整数12：数据长度 |
| 3 | 01 | 流水号1 |
| 4 | 26 | 前4字节的CRC8 |
| 5–8 | 00 00 00 00 | vx，float32 |
| 9–12 | 00 00 00 00 | vy，float32 |
| 13–16 | 00 00 00 00 | wz，float32 |
| 17–18 | 18 9F | CRC16为0x9F18，低字节在前 |

上行帧不包含cmd_id；三个float共12字节。CRC16覆盖前17字节，包括CRC8。

2. 运行测试，确认两组官方非零帧、修正后的停车帧和CRC自检值全部通过。
3. 修改seq，观察帧头CRC8和整帧CRC16的变化。
4. 修改vx为1，找到`00 00 80 3F`，它是1.0的float32小端编码。

无需现在推导CRC数学原理，先理解其参数、覆盖范围和用途。

## 文档中的停车帧差异

赛务文档第5节的停车示例包含13个数据零字节，整帧实际为20字节；第2节规定数据段只能是12字节、整帧19字节。
本项目按第2节结构使用12个零字节，生成的CRC16为0x9F18，与文档末尾的`18 9F`一致。
另两组非零示例帧及CRC自检值均与文档一致。接车前建议向赛务确认该停车示例笔误。

依据：赛务提供的`navigation_protocol.md`第2、5、6节。

## 第二步：控制保护层

运行：

```powershell
python demo_safety.py
python -m unittest -v
```

演示使用模拟时间，会立即打印结果，不需要等待、不操作串口。
会依次展示启动归零、正常指令、过大指令限幅、停止更新后超时归零、新指令恢复、异常归零和主动停止。

数据流程：导航算法 → SafetyController → pack_command → 19字节帧。

`update(vx, vy, wz)`只在收到导航算法的新结果时调用；`build_frame()`供未来发送循环调用。
打包或读取不会刷新更新时刻，避免旧指令被发送循环误认为新指令。
正常代码使用`time.monotonic`计时，不受系统校时影响。

当前策略：

- vx和vy分别限制在[-0.2, 0.2]；这是起步控制量，非m/s，也非验证过的安全速度。
- 每轴独立限幅，不等于合成运动大小限制。
- wz固定为0，因为比赛下位机目前忽略它。
- 任一输入为NaN或Inf，立即清除整条运动指令。
- 距新指令更新达到500 ms时保守归零，持续打包零速直到有新指令。
- stop清除指令；它不是锁定式急停，新update仍可恢复控制。

本步学习重点：`max/min`限幅、`math.isfinite`检查、记录上次更新时间、比较时间差。
保护层只是生成正确的零速帧。实际发送、退出补发和硬件急停尚未实现，程序崩溃或断线后不能保证停车。

## 第三步：100 Hz离线输出循环

```powershell
python offline_sender.py
python -m unittest -v
```

演示运行约2秒，仅把帧保存在内存，循环结束后才打印结果，避免逐帧打印干扰周期。
启动200 ms内零速，200～600 ms持续更新运动指令；600 ms后模拟导航停止更新。
最后一次更新约500 ms后（约1.1秒）自动输出零速；退出时额外生成一帧零速。
演示中的导航更新是轻量模拟，未来真正的雷达和导航计算应在发送循环之外完成。

目标周期10 ms，使用monotonic时钟。输出耗时或系统调度导致落后时不连续补帧，留出间隔。
实现保守地在每次输出完成后留出至少10 ms，所以实际频率可能低于100 Hz。
程序打印真实周期和频率供观察，不保证Windows上的实时性，也不代表真实串口发送性能。

本步学习：循环、time.sleep、单调时钟、目标频率与实际频率、try/finally退出清理。
周期零速帧来自保护层，发送循环不会刷新导航指令的更新时间。
异常时仅在循环仍能执行、输出接收端可用时尽力输出零速；强制终止或断线不能保证送达。

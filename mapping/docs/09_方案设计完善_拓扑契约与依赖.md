# 预建图方案设计完善：拓扑、契约、闸门与依赖

本文是对现有候选实现的**设计层完善**，只描述"设计是什么、依赖什么、现场要验什么"。
**不修改任何代码**；所有引用都指向当前代码的实际行为，与代码不一致的地方在第 8 节单独列出。

设计依据：`README.md`、`AGENTS.md`、`docs/07_问题审核与新版设计.md`、`docs/08_现场验收与注意事项.md`、
以及 `premap.launch.py` / `premap_bridge.py` / `premap_core.py` / `map_bundle.py` 的实际实现。

---

## 1. 方案定位

**一句话**：赛前用原遥控器慢速扫场，SLAM Toolbox 生成 2D 地图并保存；赛时加载该地图，AMCL 重新定位，
按地图坐标执行有序八字。

与另外两条路线的根本差别：

| | 本方案（预建图） | 运行时检测 | 纯测量 |
| --- | --- | --- | --- |
| 杆位来源 | 保存的地图上**人工点选** | 雷达实时检测 | 赛前卷尺测量后写配置 |
| 全局定位 | **AMCL** 在保存地图上重定位 | 无（LIO 里程计） | 无（LIO 里程计） |
| 是否需要建图 | **需要**（赛前一次） | 不需要 | 不需要 |
| 赛时对雷达要求 | 需稳定扫描供 AMCL | 需看到两根杆 | 只需里程计 |
| 换场地/挪杆 | **必须重新建图并重新选点** | 自适应 | 重新测量 |

**本方案的核心假设**：场地与地图固定不变（规则第 1 页表格明确"导航场地与地图固定不变"）。

## 2. 两级配置的职责边界（设计要点）

这是本方案最早需要理解的一点：**存在两组配置，管的是不同的事**。

| 配置文件 | 管什么 | 内容 | 何时定 |
| --- | --- | --- | --- |
| `config/infrastructure.json` | **输入与坐标桥接** | 输入话题名、输入帧名、隔离后的帧名、两组外参、扫描高度带、点云准入预算 | 现场核实 LIO 后 |
| `config/premapped.json` | **任务与安全** | 帧名（须与上面一致）、定位质量阈值、启动闸门、点云过滤、速度与限幅 | 与上面同步，其余离线可定 |
| `maps/*.manifest.json` | **地图内容指纹** | `yaml_sha256` / `image_sha256` / `map_digest` | 建图后生成 |
| `config/field_measured.json` | **现场几何** | 停车位、两杆中心、安全矩形、`pole_radius`、`robot_radius`、`margin`、`body_from_command` | 在地图上点选 + 标定后 |

**设计约束**：`premap.launch.py:33` 会强制校验 `map_frame`/`odom_frame`/`base_frame` 在两组配置中一致，
不一致直接拒绝启动。这防止"任务配置指向一个帧、桥接却发另一个帧"的静默错配。

## 3. ROS 图与数据流

### 3.1 帧隔离设计（本方案最关键的架构决定）

```
race_map  ──(AMCL 或 SLAM Toolbox 广播)──▶  race_odom
race_odom ──(bridge 广播)──────────────▶  race_base
race_base ──(bridge 静态广播)──────────▶  race_lidar
```

隔离手段与理由（对应 `premap_bridge.py:31-35` 的校验）：

- 目标帧名必须**互不相同、非空、无前导斜杠**；
- `odom_frame` 不得等于 `input_odom_frame`、`base_frame` 不得等于 `input_body_frame`
  → **强制用独立命名空间，避免与原 TF 树出现两个权威发布者**；
- **不发布伪造的静态 `map→odom`**，也**不把 `camera_init` 直接改名成 `map`**；
- `race_lidar` 是"物理原点与轴向已确认相同"的**别名**，真实安装关系由 `base_from_lidar` 表达
  （`premap_bridge.py:123-125` 只改 `header.frame_id`，不动几何）。

### 3.2 `stage:=mapping`（建图阶段）

| 节点 | 包 | 订阅 | 发布/广播 |
| --- | --- | --- | --- |
| `race_lio_bridge` | 本项目 | `odom_topic`、`cloud_topic` | `/race/odom`、`/race/points`、TF `race_odom→race_base`、静态 TF `race_base→race_lidar` |
| `race/pointcloud_to_laserscan` | `pointcloud_to_laserscan` | `/race/points` | `/race/scan` |
| `race/slam_toolbox` | `slam_toolbox` | `/race/scan`、TF | `/race/map`、TF `race_map→race_odom` |

`pointcloud_to_laserscan` 关键参数（`premap.launch.py:46-50`）：`target_frame=race_base`、
高度带取 `scan_min_height`~`scan_max_height`、`range_min=scan_range_min`、`range_max=12.0`、
`angle_increment≈0.0087 rad`、`use_inf=True`。

### 3.3 `stage:=localization`（定位阶段）

| 节点 | 包 | 订阅 | 发布/广播 |
| --- | --- | --- | --- |
| `race_lio_bridge` | 本项目 | 同上 | 同上（**建图与定位共用同一个桥接**） |
| `race/pointcloud_to_laserscan` | 同上 | `/race/points` | `/race/scan` |
| `race/map_server` | `nav2_map_server` | — | `/race/map` |
| `race/amcl` | `nav2_amcl` | `/race/scan`、`/race/map`、`/race/initialpose` | `/race/amcl_pose`、TF `race_map→race_odom` |
| `race/lifecycle_manager_localization` | `nav2_lifecycle_manager` | — | 自动配置并激活 `map_server`、`amcl` |
| `premap_quality.py` | 本项目 | AMCL 位姿、扫描/地图、里程计 | `/race/localization_valid`、`/race/localization_status` |

AMCL 关键参数（`premap.launch.py:65-71`）：`OmniMotionModel`（与麦轮全向底盘匹配）、
`set_initial_pose=False` + `always_reset_initial_pose=True`、粒子 500~2000、`max_beams=90`、
`likelihood_field` 模型、`laser_min_range=0.4`、`laser_max_range=12.0`。

### 3.4 TF 权威分配（必须遵守，否则互相打架）

| 变换 | **唯一**发布者 |
| --- | --- |
| `race_map → race_odom` | 建图阶段：SLAM Toolbox；定位阶段：AMCL。**两者不可同时运行** |
| `race_odom → race_base` | `premap_bridge` |
| `race_base → race_lidar` | `premap_bridge`（静态） |

**设计要点**：建图与定位**不能同时启动**——否则会出现两个 `race_map→race_odom` 发布者。
这一条在 README 第 24 行有明确说明。

### 3.5 失败即停（fail-closed）

`premap.launch.py:41-42`：桥接进程一旦退出，立即触发 `Shutdown` 事件关掉整个 launch。
**不自动重启、不自动恢复运动。** 这是刻意的设计——输入断了就不该继续跑。

## 4. 输入契约（桥接的准入条件）

桥接对每个输入做**显式校验**，不满足即拒绝该帧并计数（`premap_bridge.py:78-81`，
每 50 次错误打印一条，不刷屏）。这些条件就是"现场必须核实"的清单：

### 4.1 里程计（`odom_topic`）

| 条件 | 出处 | 不满足的后果 |
| --- | --- | --- |
| 时间戳为可解释的 ROS 时间、且新鲜 | `premap_bridge.py:75` 调用 `message_stamp(...,.5)` | 拒绝该帧（不伪造 TF） |
| `header.frame_id == input_odom_frame` | `:86` | 拒绝——**实测帧名必须与配置一致** |
| `child_frame_id == input_body_frame` | `:86` | 拒绝 |
| 时间戳**严格递增** | `:88` | 拒绝（并提示"重启建图或定位"） |
| `base` 平面倾斜 ≤ 0.3 | `:96` | 拒绝（超出平面 AMCL 的适用前提） |

**不发布协方差**（`:107` 注释明确"Deliberately no fabricated covariance / velocity"）——
AMCL 用的是 TF，不是这个协方差。

### 4.2 点云（`cloud_topic`）

| 条件 | 出处 | 说明 |
| --- | --- | --- |
| 类型为 **`sensor_msgs/PointCloud2`** | `:48`、`:62` | **硬编码**，见第 8 节 |
| `header.frame_id == input_lidar_frame` | `:117` | 原始点云必须已在配置的物理雷达帧里 |
| `0 < width × height ≤ max_input_points` | `:119` | 准入预算，当前 300000 |

### 4.3 全局前提

| 项 | 要求 | 出处 |
| --- | --- | --- |
| `frames_confirmed` | 必须 `true` | `:24-26` |
| `extrinsics_confirmed` | 必须 `true` | 同上 |
| `timestamps_confirmed` | 必须 `true` | 同上 |
| `body_from_base` / `base_from_lidar` 四元数 | 必须单位长度 | `:27-30` |
| `use_sim_time` | 必须为真墙钟 | `:55-56` |

**三个 `*_confirmed` 默认全 `false`，软件不会自动置真**（README 第 60 行）。

## 5. 地图与坐标契约

### 5.1 地图包（`map_bundle.py`）

保存时生成三个文件：`*.yaml` + `*.pgm` + `*.manifest.json`。

`manifest` 含三个内容指纹（`map_bundle.py:90-95`）：

| 字段 | 含义 |
| --- | --- |
| `yaml_sha256` | YAML 文件内容哈希 |
| `image_sha256` | PGM 图像内容哈希 |
| `map_digest` | 由 `data/width/height/resolution/origin` 计算的**地图语义指纹** |

**加载时逐项比对**（`map_bundle.py:69-71`），任一不符即报
`map bundle changed: <字段>; recapture field coordinates and regenerate manifest`。

**设计含义**：地图一改，之前点选的停车位/杆位**全部失效**——因为坐标是绑在这张图上的。
这防止"换了地图却沿用旧坐标"的静默错误。

### 5.2 任务侧的地图校验（`premapped.json`）

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `map_required` | `true` | 必须有地图 |
| `map_topic` | `/race/map` | 地图话题 |
| `unknown_blocked` | `true` | 未知格视为不可通行 |
| `occupancy_threshold` | `50` | 占用判定阈值 |
| `map_max_cells` | `100000` | 障碍格预算，超限停止而非静默丢弃 |

### 5.3 现场几何（`capture_field.py` → `field_measured.json`）

在地图上**依次点选**：停车中心 → 下杆中心 → 上杆中心 → 安全矩形内角 A → 对角 B。

设计要求（README 第 104–110 行）：

- `pole_radius` 取**底座保守最大半径，不是细杆半径**；两个底座大小不同时取较大者；
- `robot_radius` 必须含整车突出部分，**xacro 的 0.29 m 只是模型下限**，不等于整车；
- `margin` 必须覆盖定位、感知、制动、跟踪误差；
- `body_from_command` 单位是"**m/s 每单位协议控制量**"，默认矩阵只表示轴向关系，**不是速度标定**；
- 速度默认 `max_speed_mps=0.05`/`control_limit=0.05` 是**调试档**；超过 0.2 需设置已实测的
  `commissioned_control_limit`（本实现上限 1），**不得外推未测试范围**。

## 6. 定位质量与启动闸门

### 6.1 定位质量的设计立场

`premap_quality.py` 综合**四个独立来源**生成 `/race/localization_valid`：

1. AMCL 真实协方差（`quality_monitor.max_position_variance=0.04`、`max_yaw_variance=0.1`）
2. 扫描/地图端点一致性（`localization_gate.min_match=0.45`）
3. 里程计时效
4. **稳定等待**（`localization_gate.dwell=1.0` 秒、`max_age=0.8`）

**设计要求**（README 第 137 行）：

> 定位心跳依据真实 AMCL 协方差、扫描/地图端点一致性、里程计时效和稳定等待生成；
> 是**质量启发式，不是绝对真值**。**禁止永久手发 True**，也不能拿 FAST-LIO 的全零协方差冒充全局定位。

`accept_zero_covariance=false`：零协方差**不被解释成高精度**。

**已知局限**（docs/08 第 11 行）：协方差小不等于定位正确；扫描/地图一致性
**不能排除对称环境的误匹配**。这一条无法靠软件消除，只能靠现场多次重启验证。

### 6.2 四项启动确认（`premapped.json:28-31`）

`field_confirmed`、`calibration_confirmed`、`lidar_extrinsics_confirmed`、`emergency_stop_confirmed`
——默认全 `false`，**必须实测后才置真**，软件不会自动置真。

### 6.3 起跑触发

**一次明确的 start 服务**（`/srm_navigation/start`），之后不接受人工运动修正。
**不解释 `game_progress`、不开机自动跑、不捏造语音起跑语义**（docs/07 第 23 行）。

## 7. 时序与状态

### 7.1 全流程时序（含前置条件）

```
【赛前一次】
  ①环境自举  bootstrap_dependencies.py → .deps/python310（离线wheel，不需sudo）
  ②核实输入  ros2 topic list -t / topic echo / topic info
              → 填 infrastructure.json 的话题名+帧名+两组外参 → 置三个 *_confirmed
  ③遥控建图  ros2 launch premap.launch.py stage:=mapping
              → 慢速扫全场 + 回环 → 检查重影、杆与底座可见性（不调低标准掩盖盲区）
  ④存图      python3 run.py map_bundle.py --output maps/<name>
  ⑤点选坐标  stage:=localization + capture_field.py → field_measured.json
  ⑥标定      calibrate_motion.py（双轴正负稳态样本）+ 死区/回差/电量/停车距离
  ⑦离线预检  premap_vehicle.py --check（不开串口，只查地图覆盖/未知区/路线碰撞）

【赛时每轮】
  ⑧加载地图  stage:=localization bundle:=<manifest>
  ⑨给初值    RViz 2D Pose Estimate → /race/initialpose（初值 ≠ 定位结果）
  ⑩等就绪    /race/localization_status、/navigation/status 到 READY
  ⑪一次触发  ros2 service call /srm_navigation/start
  ⑫自主执行  下瓣逆时针 → 上瓣顺时针 → 交叉点按序 → 回停车位 → 持续零速
  ⑬记录      轨迹、绕杆方向、圈数、停车误差、用时、故障
```

### 7.2 关键状态语义（`premapped.json` 与代码）

| 状态 | 含义 |
| --- | --- |
| `WAIT_POSE` | 位姿未就绪/过期 |
| `WAIT_LOCALIZATION_QUALITY` | 质量心跳未就绪 |
| `WAIT_OBSTACLES` | 障碍数据未就绪 |
| `WAIT_MAP` | 地图未收到 |
| `BLOCKED` | 必经点被占据 → **等待，不跳点** |
| 故障锁定 | 串口异常、**真实位姿跳变**、轨迹碰杆/出界 → 锁定，**不自动恢复** |

**设计立场**（docs/07 第 20 行）：保留真实跳变锁定，避免在错误定位下自动重启；
**普通临时障碍/短暂定位失效可暂停恢复**；不能为考核避障而取消跳变保护。

### 7.3 数据时效设计

- 所有计划/指令**保留原始数据截止时间**，计算完成**不得重新赋"新鲜"时间**（AGENTS.md 第 6 条）；
- 点云用**单在途 + 单最新待处理**、队列有界（`premap_core.LatestWorker`）；
- `OutputPermit` 统一约束输出许可，受**最早截止**约束（位姿/障碍/定位质量/计算开始时间取最严）。
- 线程、GIL、操作系统**仍不是硬实时系统**（docs/08 第 26 行）。

## 8. 与当前代码不一致 / 需要现场确认的关键项

> 本节是本文最重要的部分。以下每一条都会**直接决定方案能否在现场跑起来**。

### 8.1 ⚠️ 点云话题与消息类型（最高优先级）

| 项 | 配置/代码假设 | 现场已知情况 |
| --- | --- | --- |
| 话题名 | `infrastructure.json` → `cloud_topic` = `/livox/lidar/pointcloud` | 实测存在的是 **`/livox/lidar`** |
| 消息类型 | `premap_bridge.py:48,62` **硬编码 `PointCloud2`** | 实测 **`livox_ros_driver2/msg/CustomMsg`** |

**影响**：`create_subscription(PointCloud2, ...)` 订阅一个 `CustomMsg` 话题**不会收到任何数据**，
桥接会一直拒绝帧、`/race/points` 无输出 → 建图阶段无法产生 `/race/scan` → SLAM 无输入。
**这是当前唯一的"硬卡点"。**

**必须现场确认的三件事**：

```bash
# ① 是否存在一个 PointCloud2 格式的点云话题（可能由驱动另一种输出格式提供）
ros2 topic list -t | grep -iE "livox|cloud|points"

# ② 若只有 CustomMsg：确认驱动能否同时/改为输出 PointCloud2
ros2 topic info /livox/lidar -v
ros2 param get /livox_lidar_publisher xfer_format      # 若节点名不同请按实际替换

# ③ 确认点云 header 里的 frame_id（必须等于 input_lidar_frame）
ros2 topic echo --once /livox/lidar --field header.frame_id
```

**三条可选路径**（需你与赛务/器材负责人确认哪条允许）：

| 路径 | 做法 | 代价 |
| --- | --- | --- |
| A | 找到/启用驱动已有的 PointCloud2 输出话题 | 需确认驱动参数与是否影响他人 |
| B | 在本项目内增加 CustomMsg→PointCloud2 的转换节点 | **需要改代码**（当前指示为不改） |
| C | 加一层 `pointcloud_to_pointcloud2` 之类的公开转换 | 需确认现场 `xfer_format` 的实际含义 |

**在设计层面，这一条必须先定**，因为它决定桥接的输入契约是否成立。

### 8.2 输入帧名必须现场核实

`infrastructure.json` 里 `input_odom_frame=camera_init`、`input_body_frame=body`
**目前是候选值**（文件第 2 行自述 "EXAMPLE ONLY"）。

需要 `ros2 topic echo --once <odom_topic>` 的 `header.frame_id` / `child_frame_id` 实证。
注意：这两个值**可能与 `/Odometry` 的实际内容不同**（不同 LIO 发行版命名不同）。

### 8.3 两组外参都是占位值

| 参数 | 当前值 | 性质 |
| --- | --- | --- |
| `body_from_base.xyz` | `[0, 0, -0.4]` | **占位**，±0.4 m 是示例 |
| `base_from_lidar.xyz` | `[0, 0, 0.4]` | **占位** |

`extrinsics_confirmed=false` 会阻止启动。必须实测：雷达中心相对车体的安装位姿。
**注意 docs/08 第 30 行的禁止项**：不能把 xacro 可视模型的 mesh 偏移当成外参。

### 8.4 其他已知的开放项

| 项 | 状态 | 依据 |
| --- | --- | --- |

## 9. 现场验收闸门（11 道，摘自 docs/08）

按顺序通过，**未通过不得把确认开关置真**：

1. **独立停车能力**——明确谁能操作急停、如何恢复；不能用拔 USB 代替急停
2. **软件与设备隔离**——个人目录、公开驱动、确定 by-id；不终止他人进程
3. **零速通信稳定**——独占打开、观察 CRC 正确反馈计数；DTR/RTS 含义实测
4. **控制权限与小范围响应**——低量单轴短脉冲，验证符号/双轴/死区/急停；`wz` 无效
5. **传感器/坐标/时间**——真实话题、帧、外参、时间；TF 单一发布者；地面不冒充障碍
6. **建图**——覆盖全程与回环、无明显重影、两个底座清楚；布局不能建图后随意挪动
7. **重启定位**——停建图、只开地图服务器/AMCL、车回起点、给真实初值、多次重启稳定
8. **完整静态预检**——参考路线、未知区、底座、整车外廓、边界；裕量覆盖实测误差与停车距离
9. **低速单圈闭环**——无动态干扰下验证完整有序八字、交叉点次数、回停车位、持续零速
10. **干扰与故障验收**——受控测试障碍/遮挡/定位丢失/串口异常；**人工接管=终止本轮，不是完成**
11. **比赛档**——在已验收速度区间逐步提速；保留低速档便于排错

每一项建议记录：日期、操作者、输入配置哈希、视频/日志位置、结果。

## 10. 设计层风险清单

| 风险 | 性质 | 现有设计如何应对 | 残余风险 |
| --- | --- | --- | --- |
| 点云类型不匹配 | **硬卡点** | — | 见 8.1，必须现场解决 |
| 对称环境 AMCL 误匹配 | 算法固有 | 质量心跳 + 多点选交叉验证 | **无法软件排除**，需现场多次重启 |
| 反射弱的橙色底座 | 传感器物理 | 高度带 0.03~1.2 m | 哑光橙色在 Mid-360 上的回波强度未知 |
| 建图后挪动场地 | 流程 | 地图指纹校验 | 只能靠纪律与重新建图 |
| 定位漂移导致误判到达 | 算法 | 位姿跳变锁定 + 轨迹审计 | 缓慢漂移难以察觉 |
| 物理停车无法保证 | **硬件** | 退出补发 20 次零速 | 强杀/掉电无法补帧；**必须依赖独立急停** |
| 地图过大导致处理超预算 | 性能 | `map_max_cells=100000`，超限停止 | 需在建图时控制范围与分辨率 |
| 建图与定位同时运行 | 操作 | README 明确禁止 | 靠人工纪律 |

# 校内赛哨兵机器人导航

本仓库保存校内赛导航赛道的三套实现方案，用于版本管理、调试记录与校赛开发。



## 硬件与软件环境

| 项 | 内容 |
| --- | --- |
| 底盘 | 麦克纳姆轮哨兵（四轮 45° 倾斜，全向移动） |
| 主控 | Intel NUC，Ubuntu 22.04，ROS 2 Humble |
| 雷达 | Livox Mid-360，点云话题为 `livox_ros_driver2/msg/CustomMsg` |
| 下位机 | 由赛务统一提供，串口 **115200 / 8 数据位 / 无校验 / 1 停止位 / 无流控** |
| 外部定位 | 现场提供 Livox 驱动与 FAST-LIO，输出里程计与 TF |

---

## 三个方案

三套实现解决的是**同一个任务**，差别在于"障碍杆的位置从哪里来"。

| 目录 | 杆位来源 | 依赖 | 定位与说明 |
| --- | --- | --- | --- |
| **`measurement_only/`** | 赛前用卷尺测量，手工换算成坐标写入配置 | 仅需串口与里程计 | 不需要地图、不需要视觉。**保底方案**：链路最短、环节最少，但没有自适应能力 |
| **`full_autonomous/`** | 运行时从点云中实时检测杆 | 激光点云 + 里程计 | 自主感知两根底座并跟踪，含检测器、跟踪器与离线验证工具 |
| **`mapping/`** | 赛前遥控建图后在保存的地图上点选 | `slam_toolbox` / `nav2_amcl` / `pointcloud_to_laserscan` | 赛前采集二维导航地图，赛时加载地图重定位后执行八字。|
> **三个目录是彼此独立的实现，不能混用配置、启动入口或测试结果。**

```
.
├── measurement_only/        方案一：测量坐标，最小依赖
├── full_autonomous/         方案二：运行时感知障碍杆
├── mapping/                 方案三：赛前建图 + 赛时重定位
└── README.md
```

`measurement_only/` 与 `full_autonomous/` 共享同一套底层模块：

```
navigation_protocol.py   19 字节下行帧的打包 / CRC 校验
feedback.py              上行帧解析（cmd_id 0x0001 / 0x000B）
serial_link.py           串口收发线程、异常分级、停车帧补发
safety_control.py        输出许可、看门狗与故障锁定
vehicle_core.py          车辆状态机、点云裁剪、里程计新鲜度
navigation.py            8 字路线生成、A* 寻路、纯追踪控制
robot_model.py           从 xacro 读取整车外廓
real_vehicle.py          ROS 2 实车适配层
main.py                 统一入口（test / simulate / feedback / serial）
```

## 当前状态与安全边界

**这是调试中的软件代码，不是已经完成实车比赛验收的成品。**

- 遥控器控制车辆：已验证可以正常运动。
- 串口接收：已有成功接收记录，也出现过间歇性异常。
- 通信帧生成：发送帧与协议文档的参考向量逐字节一致。

- 仿真结果与桌面测试**不能**证明真实串口控制、定位、避障或停车已经通过。

- **安全须知**

- 协议没有超时保护，程序异常退出时下位机可能继续保持最后一条运动指令。
- 程序会在退出、异常与 Ctrl-C 时补发零速帧，但**USB 断开或电脑掉电时软件无法保证停车**。
- 因此实车调试必须配备
- 首次运行或改动控制量后，先架空车辆或用 `--sweep` 小幅度分级验证方向与量级。
